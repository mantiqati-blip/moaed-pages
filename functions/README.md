# دوال موعد أنوثة (تحتاج خطة Blaze)

**الحالة:** مكتوبة ومختبرة منطقيًا (`npm test` داخل هذا المجلد، ٥ اختبارات). **لم تُنشر ولم تُجرَّب على Firebase.**

## النشر
1. رقّي المشروع إلى Blaze، وضعي حد صرف بالفوترة.
2. `npm i -g firebase-tools` ثم `firebase login` ثم `firebase use moaed-unotha-prod`.
3. من مجلد المستودع: `cd functions && npm install`، ثم `firebase deploy --only functions`.
4. فهرس Firestore: أول طلب حجز قد يفشل برابط لإنشاء فهرس مركّب (`customerPhone` + `status` + `start`). افتحي الرابط واضغطي Create.

## التحويل التدريجي (بدون كسر الموجود)
1. انشري الدالة فقط. الواجهة تبقى على الطريقة القديمة.
2. من لوحة الأدمن (أو بـ Firebase Console على `platform/settings`) ضعي `useServerBooking: true`. صفحة الزبونة تنتقل لاستدعاء الدالة.
3. جرّبي حجزًا كاملًا: النجاح، وحجز وقت مأخوذ (SLOT_TAKEN)، وأربعة حجوزات بنفس الرقم (الرابع يُرفض).
4. بعد نجاح التجربة فقط، شدّدي القواعد: امنعي إنشاء `bookings` بـ `source == 'online'` و`bookings/*/private/code` من العميل، وامنعي الكتابة على `schedules` للزبونات. (الدالة تكتب بصلاحية السيرفر فلا تتأثر.) التعديل والنقل ما زالا يكتبان الجدول من العميل وبحاجة دوال مستقلة لاحقًا.

## ما تفرضه الدالة
السعر والمدة من بيانات الصالون لا من العميل، وساعات الدوام، والموظفة الفعّالة، والرسم والاستقطاع من قيمة الصالون أو الافتراضي، وتحقق الهاتف عند تفعيله، وحد ٣ حجوزات مؤكدة قادمة للرقم الواحد، وتوليد رمز الإكمال من السيرفر، والحجز المزدوج بـ Transaction.

## تصفير الحساب من السيرفر (`closePeriod`)
- للأدمن فقط. السيرفر يقرأ الحجوزات والتسديدات ويعيد الحساب بنفسه ويرفض إذا المتبقي لا يساوي صفرًا. اختبار منطقه: `npm test` (٦ اختبارات).
- التفعيل: ضعي `useServerClose: true` بوثيقة `platform/settings`. زر «تصفير الحساب» عند الأدمن يستدعي الدالة بدل الكتابة المباشرة.
- بعد نجاح تجربة تصفير واحدة، شدّدي القواعد: `allow create: if false` على `salons/{sid}/periods` (الدالة تكتب بصلاحية السيرفر فلا تتأثر).
